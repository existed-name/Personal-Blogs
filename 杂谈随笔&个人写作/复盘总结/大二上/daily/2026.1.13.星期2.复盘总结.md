## 1、DQL
### （1）聚合函数
#### ①基本语法
```sql
select 聚合函数( 要查询的字段 ) from 表名;

# 不能同时查询普通字段、聚合函数，除非把普通字段放进group by
❌select 其他字段, 聚合函数 from 表名;
✔️select 字段, 聚合函数 from 表名 group by 字段;
```

#### ②常用函数
```sql
# 函数名(待查字段作为参数)--作用
count		统计数据的个数（行数）
min/max		最小/大值
sum			求和
avg			平均值
# 感觉有点像Excel
```
👆上述函数**统计某个字段**的相关数据时，**会忽略null**

#### ③统计表格行数
`count( * )`  =  `count( 任意常量比如1、'a' )`  = 当前表格总行数 >= `count( 字段 )`（可能有null，于是会少记录）


### （2）分组查询
#### ①从基础的`group by`开始
```sql
# 按照指定字段的取值，把表格分成几组（相同取值为1组，类似去重）
select 分组字段1, 2, 3... from 表名 group by 分组字段1, 2, 3...;
# 然后展示分组情况，即这个字段去重后的取值情况（毕竟查询的就是这个字段）
❌select 其他字段, 分组字段 from 表名 group by 分组字段;
⚠️分组后，每个分组字段对应了多个其他字段，SQL 不知道该选哪一个

# group by跟distinct有点像
select distinct 查询字段1, 2, 3... from 表名;
# 都是去重、展示指定的字段（集），都不允许出现其他字段，甚至cmd展示出来的都是一样的
❌select 其他字段, distinct 查询字段 from 表名;
# 但⚠️distinct 只是去重，group by 是为了分组 + 聚合函数统计每组数据
```

#### ②混合聚合函数、条件
```sql
# 先初步过滤，再分组
select 分组字段 from 表名 where 条件 group by 分组字段;

# ⭐select查询的字段，只能放在聚合函数里面，或者作为分组字段
select 分组字段, 聚合函数( 其他字段 ) from 表名 group by 分组字段;
# 展示由分组字段、聚合函数组成的表格
# 这里也可以加上 where 进行初步过滤
```

#### ③`having`关键字
```sql
# 对初步过滤 + 分组后的表格 进行筛选
select 分组字段	# 如果还想查看字段对应的统计数据，可以在这里加上聚合函数
from 表名
where 初步过滤
group by 分组字段
having 聚合函数( 其他字段 )及筛选条件;
```

`having`的底层实现可以看这2篇博客：  
[手写having关键字](/技术探索&评测/试一下手写`having`关键字.md)、[一道SQL分组过滤题](/数据结构与算法刷题/SQL/一道SQL分组过滤题.md)  
（昨天、今天大部分时间都用在这上面了😅）

```sql
select 目标字段, 统计结果
from (
	select 目标字段, 聚合函数 as 统计结果	# 💡取别名，方便在其他地方用（尤其是最后where筛选）
	from 表名
	where 初步过滤
	group by 目标字段
) as temp_table	# ⚠️中间产生的表必须用别名替代
where 筛选统计结果;
```

### （4）附
①每次`select`（子查询）都会获得1个表，这个表**只包含要查询的字段**  

②SQL执行顺序
> by GPT...
> 1. `FROM` (选择数据源)
> 2. `WHERE` (过滤记录)
> 3. `GROUP BY` (分组)
> 4. 聚合函数 (如 `avg`, `sum` 等；**先分组再计算聚合函数**)
> 5. `HAVING` (分组后的过滤)
> 6. `SELECT` (选择最终需要的列)
> 7. `ORDER BY` (排序)  

③`where`里面不能用聚合函数，因为根据执行顺序，找个时候还没有算出函数结果

④`where`分组前初步过滤，`having`分组后筛选
