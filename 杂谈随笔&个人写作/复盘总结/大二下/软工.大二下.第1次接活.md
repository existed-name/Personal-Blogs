# (一)4.18.星期6
## 1、来活
对接的学长暂时没帮我找到简单点的项目(老好人学长~)，于是趁着接近2个星期的缓冲期，优化自己的管理系统学习项目(界面、异常处理之类的)，然后忙着学习虚拟机部署项目

下午打完球🏸、干饭、洗澡、收拾东西，20点坐到电脑面前，发现16点过的时候来了一个项目，不管三七二十一，赶紧接下再说——虽然原来的项目还没部署完，但机会来了总不能放走

根据对方的聊天记录，先整理下粗糙的需求描述，然后接过压缩包


## 2、启动🔋
是SpringBoot + Vue项目，需要优化前端界面、新加点功能

有了上次跑通项目的经历，这次要舒服一点。打开项目、加载Maven配置、没加载上的配置就右键`pom.xml`然后`Add as maven project`、修改`application.yml`的数据库密码、新建数据源然后运行db文件夹的`.sql`文件装好数据。然后启动后端说端口被占用，想起虚拟机用到了部分端口，于是把虚拟机、FinalShell关了，之后跑通后端

再来到`src/main/resources`，看到这里的admin后台、front前台界面，打开Terminal，目前是Node22，先试一下`nvm install`，发现可以下载，不过等着等着不对头，它一直卡在那里转圈圈

复制控制台信息发给AI，可能是Node版本太高不兼容，于是切换到Node14(而且也看到了眼熟的老旧的`node-sass`)，然后`npm install --legacy-peer-deps`，还好成功

跑通整个项目，睡觉~~~



# (二)4.19.星期7
## 1、一脸懵逼的数据库
昨天还跑通，今天管理员身份运行cmd启动MySQL的时候失败

```bash
C:\Windows\System32>net start mysql
发生系统错误109。
管道已结束。
```

我寻思着就算弄个虚拟机，也应该是昨天影响的啊，关今天什么事……

然后听AI的，跑到MySQL安装目录的`bin`里面，执行`mysqld --console`启动`mysqld`并输出错误日志；再`sc query mysql`查看MySQL服务详情；甚至执行`eventvwr`去`事件查看器` → `Windows 日志` → `应用程序` → 右侧栏`查找`搜索MySQL相关事件……

以及继续尝试启动

```bash
C:\Windows\System32>net start mysql
MySQL服务正在启动...
MySQL 服务无法启动。
服务没有报告任何错误。
请键入NETHELPMSG3534 以获得更多的帮助。
```

我看AI给的方法，停止、删除原服务再重装、注册服务，感觉有点危险，于是再试下启动，没想到就好了……

```bash
C:\Windows\System32>net start mysql
MySQL服务正在启动...
MySQL 服务已经启动成功。
```

合着多启动几次就能解决问题……


## 2、一脸懵逼的我
本来还在想，主要是改几个界面的导航栏，应该不难，虽然前端只有“了解”的水平，但让AI做总是可以的

然后细看粗糙的需求（当然别人画的很清晰了），emm，暂时没有脑子，先让IDEA的AI插件提取1个接口文档，放着之后用（后来发现好像用不到）。然后再去前端界面逛一逛，怎么去掉这个下拉列表原来的选项，把另一个按键带着链接，合并进来；然后对方描述的导航栏、下拉列表真的合理吗，有这个界面吗、要自己做吗

于是又让插件分析了下前端文件，看看各个view是什么，然后发现对方描述的界面确实已经有了，但部分界面路由配置里有，前端界面就是没有它的入口、要从浏览器路径来访问……

继续转动脑子，不知道该从哪里下手……

拖了挺久的，emm，可能是我对需求的认识还不够，于是开始详细观察对方的画、目前的界面，比较，记录`当前情况`（导航栏排版怎么样、点击1级目录的下拉列表怎么样）、`预期`，以及各个界面在文件夹里面的相对路径(`src/views/xxx`文件夹)、浏览器访问路径……这样稍微清晰了点，已经写出了比较细的提示词——然后我才想到，网页端AI肯定是用不了了，文件太多发不过去，还是得用AI插件读我的代码库（对Agent代理之类的不熟悉，还得多练）

有点思路了……


## 3、做好备份
要让AI插件操作我的代码库，除了提示词，肯定要备份好代码，方便回退。于是去配置Git（是的，一直都还没弄这个😅）

一步一步问AI、安装好Git，然后IDEA → `Settings` → `Version Control` → `Git` → 设置`Path to Git Executable`为Git安装目录的`bin/git.exe` → `Test`成功后`Apply`。再IDEA上面菜单栏 → `Version Control` → 创建仓库 → 选当前项目文件夹；网页端GitHub创建private空仓库 → 把URL拿下来配置上……

总之，弄个配置又是这一天的极限了……


# (三)4.20.星期1
## 1、继续备份
**(1)**

IDEA左侧`Commit`面板，`Commit & Push`所有文件，提示设置GitHub账户名、noreply邮箱(最开始设的自己的邮箱，报错，发现要用GitHub的noreply邮箱替代自己的邮箱保证隐私性)

想到是第1次用Git（虽然是用编译器操作），一点点成就感~~~

然后就报错了

**(2)隐藏ESLint报错**

`Code Analysis`有很多errors，一看，应该都是前端的。但是不应该啊，为什么报错都还可以正常跑

复制errors拿给AI看，说是老旧的ESLint配置典型报错，于是找到`package.json`，修改`eslintConfig`部分，关闭常见的规则，删除`node_modules`，重新`npm install --legacy-peer-deps`。emm，确实errors少了很多，但总有些漏网之鱼

于是设置 → `Editor` → `Inspections` → 修改`JavaScript & TypeScript`的`Code quality tools`的`ESlint`，把`in all scopes`的`security`从error改成warning；同样这个设置界面的`Vue`，没找到`ESLint`的设置，AI说是vue自动调用JavaScript的ESlint检查，就不用管。然而Apply后，虽然errors有少了很多，但始终清不干净

**(3)不争了**

还是用最懒的方法解决：Commit面板 → 右下角齿轮打开设置 → 取消勾选`Analyze code`、`Check TODO`，直接把“报错”的项目交上去


## 2、“写代码”
**(1)更新工具**

IDEA的AI插件一直用的通义灵码，还是去年的2.6.4，很久没用他，现在都2.11.1了，于是想，反正都要AI，那就更新一下吧，害怕我这老版本调的是Qwen3或者更低版本，写代码不够好

然后看插件评论，主要是磁盘读写占用超标，伤磁盘，再看到某评论说卸载重装可以解决这个问题，于是照做

看看更新后的插件，还是`智能问答`、`智能体`2种选项，不过可以自己去订阅然后把ApiKey弄过来切换模型（虽然只支持阿里百炼、GLM、Kimi、Minimax，不过我感觉也够了吧，更何况现在只需要用默认的模型、还没进步到那种阶段）

另外听说IDEA2026对AI插件支持、性能优化更好，我这IDEA2025.1还是再等一段时间来更新吧


**(2)有点好起来了**

拿着提示词（目前情况 + 预期效果）塞给他，先讨论几波，完全确定过后，开`智能体`模式，让它修改代码文件

先从IDEA + AI插件练起，想象一下以后用AI原生IDE的快乐（学废了）

成功以后，让他总结下commit message，然后Commit & Push，有种解脱感，然后继续写管理端界面的优化提示词……

昨天上午硬想了半天，真不如早点理清楚需求、构思提示词、然后快点AI解决需求



# (四)4.21.星期2
## 1、缝缝补补
本来我想应该快速解决战斗，但是能力有限，非常之慢，并且每天的经历也确实有价值，所以还是跑不了把这些经历记录下来。于是用了一上午把之前的经历补上——确实，不管怎么样，当天，最多第2天早上，就应该写好总结，不然过一点点时间，记忆就没那么清晰了，而且事情也多（学校作业还有一堆要做），稍微拖一拖总结，就要堆不少要补回来


## 2、乱
让AI插件再帮我看看没设置路由、设置了路由但是没入口的界面（还有这种情况，也是没招了）——因为对方描述有些功能在网页端上没看到，我又不想写，就先看一看是不是藏在文件夹里面没暴露出来——然后访问路径测试一下、看要不要添加入口。为了进一步确认，用了两三轮对话来仔细检查

比较奇怪的是，有些界面通过路径访问内容空白或者效果不符合预期，但是从已有的入口访问，就有效果

大部分时间都弄在写提示词上面去了，一天也没干什么，甚至15点~18点过打球🏸、干饭、洗澡、收拾东西，又占了大部分时间……

而且因为是之后来补的总结，所以忘掉的东西有点多，确实应该频繁commit、详细记录项目历史，起码对照一下还可以想起来自己干了什么

对了，还想起来，我看浏览器地址是`#/login`，而不是直接的`/login`,其他路径也一样会有`#`，问AI，发现是因为`router.js`里面用了hash模式



# (五)4.22.星期3
## 1、有点进展
**(1)**

对方描述admin管理端的`用户管理`，要弄一个`用户登录注册`，我想应该不是把登录的用户下线、注册的用户清除账号吧，可能是看看哪些用户登录、注册，也就是弄个登录注册日志界面

本来项目就有个系统日志界面，后端是`@SysLog`，我想的话，再原创`@LoginAndRegisterLog`、相应的Controller、表之类的太麻烦，于是后端干脆就用原来的系统日志，多弄一个分页查询登录注册日志的方法，然后前端复制原来的系统日志界面就行

**(2)**

于是让AI写了个方法——感觉也就跟直接复制源码一样——粘贴过来，我看Controller的方法有点陌生，`Wrapper`是什么、为什么用它来设置查询条件?没管，按照“正常的”思路，Controller添加方法 → Service接口添加方法 → ServiceImpl重写方法 → Mapper接口添加方法 → xml写详细SQL（复制已有的代码，然后在`<where>`标签里面补上条件——我想MyBatis-Plus应该接受我这MyBatis的操作吧）

然后复制代码，让AI一检查，才知道Mybatis-Plus是Controller里面把条件设置到Wrapper，交给框架去查询，服务类、DAO只需要简单的查询方法就行；MyBatis的话才是我这种底层多种查询方法，再Service包装上去

于是把画蛇添足的部分删了，Controller的方法直接在Wrapper设置查询`登录、注册`相关操作，然后把系统日志界面复制一份、改个文件名、把里面的后端URL改一下(怪不得我没找到专门的api  JS函数文件，都直接分散在每个view代码里面的)；原来的系统日志查询，就过滤`登录、注册`，避免重复……

**(3)**

先用ApiFox测试后端接口，返回了奇怪的HTML代码，后来发现是application.yaml设置了`context-path`，需要把它带在URL里面，所以应该访问`localhost:8080/context-path/目标路径`而不是访问`localhost:8080/目标路径`

还好测试通了，前端访问也正常。之后再整理提示词，跟AI讨论，优化导航栏，不过AI说组件设计有限制，只支持2级目录，改成3级及以上会比较麻烦。不过也是能跑就行

**(4)**

push的时候遇到了Git的网络问题(就跟国内联网偶尔进不去GitHub一样)，问AI才知道需要手动设置Git的代理端口号，让它可以访问GitHub

```bash
# 查看Git绑定的端口号
git config --global --get http.proxy
git config --global --get https.proxy

# 绑定为本地代理监听的端口号(可以在自己的端口设置查看)
git config --global http.proxy http://127.0.0.1:7897
git config --global https.proxy http://127.0.0.1:7897
```

**(5)**

晚上给学长报备，然后睡觉，这么多天了、还没干成、真的捂脸

# (七)4.24.星期5
## 1、烂尾
早上继续让AI插件修bug、不折腾原来那个比较难的bug，先修相对比较简单的……好吧，没修好

看着面前的通义灵码，我在想它调的是哪个模型版本，然后想着如果调的Claude就好了……(听说要实名认证了，不知道我的号还可不可以登上去)

折腾快2小时，算了，不争了……


## 2、总结收获
1. **IDEA + Git一些简单操作**
   * 之后单独总结博客

   * 经常commit，记录每次的文件变化

   * commit是提交变化到本地仓库，在项目根目录隐藏的`.git`文件夹里面

   * push到GitHub远程仓库

   * rollback回滚到上次提交的状态

2. **继续巩固普通项目的跑通流程**

   * Maven依赖添加成功(`Add as maven project`)

   * 创建数据源，运行`.sql`导入schema

   * 修改application.yml的数据库username、password

   * 启动后端(提前启动MySQL、关掉占用同一端口的项目)

   * 寻找项目内部的前端文件(可能在`src/main/resources`里面，admin是管理端，front客户端)

   * 在前端文件目录打开Terminal，切换Node版本(比如把package.json发给AI，看看需要哪个版本)

   * 执行`npm install --legacy-peer-deps`安装依赖

   * 启动前端

3. **IDEA + AI插件**

   * 通义灵码的智能体模式还是能用的，但我对Agent之类的了解太少，以后可以多试一下(比如再去弄点kimi/GLM的ApiKey，然后切换模型；或者试试其他插件)

   * 刚开始写提示词，我是一个一个描述当前情况、期望、文件位置；然而其实直接把需求理出来，发给他，跟他讨论规划，确定后一步一步写代码就行，文件的话他会自己读、或者添加上下文把文件夹加进来就行(最多提醒下他)；然后还是得新开个对话审核每一步的修改

   * 不过我发现，我内心还是有点“不接受”，主要在于我想自己写后端，但是又菜，最后不得不全部交给AI。然而就是这种“不接受”拖慢了整体速度

   * 我想的话，还是自己基础不够，代码敲少了，还没到用AI代做的水平(除了用AI做前端、检查代码、写脚本之类的)。简单说，菜就多练，等代码敲够了再用AI“替代”自己

4. **其他**

   * 最开始接这种项目二开，就是为了练习，但好像还是跟着各种规范的教程做比较合适，自己还没培养出那种思维、基础还不够，做二次开发就比较吃力

   * 不过感觉接项目做二开，确实锻炼快速适应新项目、了解功能流程、看懂+实现需求的能力；最起码，还可以锻炼用AI的能力[捂脸]以及多见识见识

   * 缺点是接的项目可能代码质量不高、命名以及规范性等等不太好，技术栈也比较老；然后我感觉都像是有模板、直接套进来改一改、看起来都差不多()

   * 还了解到可以在项目里面调AI接口、用vue做个对话框包装成智能对话

   * 有能力给别人价值，我能去找别人，有足够的能力高效的给别人价值，有人会来找我。可惜了能力不够，没给别人留下好印象
