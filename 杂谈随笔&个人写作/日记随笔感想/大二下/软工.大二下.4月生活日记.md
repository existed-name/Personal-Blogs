## (二)4.10.周五
### 1、对饮水机加热方式的探究
我在想可不可以纯靠推理知道饮水机放出的热水是怎么来的

1. 加热某个部件(比如管道/内胆)，放热水的时候，矿泉水经过这个部件，于是变烫
2. 加热一部分水，存起来

又想了几种测试方法

1. 根据使用经验
    * 如果热水那边放干了，但是冷水那边还有不少水
    * 那么可能是热水、冷水2部分分开存的
    * 就有可能是方式2
    * 然而想起: 曾经把饮水机的漏斗拿起来，里面有2个洞口可以进水，应该分别对应热水/冷水出水口
    * 那么就可能不是冷热水分开存，不能确定加热方式

2. 完成加热后，记录从`保温` → `加热`状态，以及关掉饮水机，热水冷掉的时间
    * 猜想如果是加热方式2，那么热水可能会比这个部件冷得更慢，于是实际可以等很久还是热水
    * 但可能低估了方式1的持久性，所以这个方法不能确定加热方式

3. 彻底放干饮水机，保持加热，再装上新的水
    * 发现热水出水口是热水
    * 于是有一定把握确定是加热方式1
    * 可能这就是`干烧`?
    * 然而，热水壶不装水直接加热，再把水直接倒进来，也可以产生热水(但不知道温度怎么样)
    * 同理，饮水机可以按照加热方式2，专门加热装热水的那个“容器”
    * 所以这个猜测也不确定
    
4. 从放水过程分析
    * 刚从冷水完成加热后的放热水过程: ①先一点点冷水、温水 → ②然后才是烫水 → ③温水 → ④冷水
    * 可不可以把阶段①看成是冷水初次经过加热部件的效果? -- 应该不可以，毕竟加热之前，就已经有冷水从饮水机内部流了进来
    * 阶段②没测温度，但根据经验，都是比较均匀的高温 -- 如果让冷水通过加热部件，那应该会是冷热不均的效果
    * 阶段③出现温水勉强可以看成足量冷水让加热部件冷却，但比较牵强
    * 保温杯500ml，杯盖80~90ml，测量热水550ml附近，我觉得饮水机里面也放得下这么大个地方专门烧热水

5. 最明显的现象
    * 加热过程饮水机有声音，特别是快好的时候，就类似热水壶烧水的那种声音
    * 所以可以直接支持加热方式1
    * 除非加热部件的声音也是这种奇怪的声音...

6. 计算题??
    * 通常加热大概5min = 300s(没具体测，可能时间少了)
    * 看饮水机背后标签额定功率500w，那么`Q = Pt = 1.5e5焦耳(150KJ)`(实际应该有不少损失)
    * 初中的比热容公式好像是`Q = c * m * ΔT`
    * 水的比热容`c = 4.184 J/(g * °C)`
    * 变化温度`ΔT = T末 - T初 = 假设100 - 假设20 = 80℃`，实际T末应该只有90多度
    * 于是`m = 150,000 / 334.72 ≈ 448g`
    * 第4点的时候已经得知热水大概550ml，也就是500来g，感觉也差不多(偶然才发现，水的密度只有0.99几)
    * 所以直接加热水是说得通的

7. 综上所述
    * 因为放水温度均匀、声音非常类似加热声音、计算结果比较接近实际
    * 所以我猜是饮水机加热水存起来，而不是加热某个部件、水流过这个部件时受热
    * 可能有没想到的地方，先这样了，反正也只是扯淡玩玩儿🤣

### 1、阶段休息
**(1)**

我发现对于1个任务，假如分成了几个重要阶段，过程比较艰难/不容易，那么到了1个阶段性成功后，我就会如释重负，放松了，然而如果趁热打铁进行下一阶段，就可能会因为放松、感觉负担轻了很多，于是没那么认真，而且注意力、精力也用不上来

这个时候应该转移注意力，干其他的事情(看书/锻炼拉伸轻微活动/写博客/继续学/下象棋/收拾东西/打扫寝室/做作业...总是有事干的)，再回来，而不是效率不高地做下一阶段任务

**(2)**

`番茄工作法`好像是25min专注(1个番茄) + 5min休息(短休)，循环4次(4个番茄)，休息15-30min(场休)

不过根据经验，进入状态的时候是很舒服的，这个时候尽情地做自己的事情，反而不需要休息，一直保持专注，直到做完，或者确实效率、专注力开始下降才需要中断。而如果在专注的时候刻意打断，可能会错过一次长时间专注的好状态

所以对我来说，还是顺其自然比较好，一直做，状态不好了就换个事情做，或者放歌补充氛围。这样就可持续发展~~~

## (二)4.21.周二
### 1、对晚上训练但是阳气收敛的探究
1. 听说
   * 下午~晚上身体活性比较大，锻炼表现更好
   * 晚上进行力量训练增肌效果更好
   * 强度比较大的锻炼是外泄阳气
   * 晚上(17~19点后)阳气收敛，不适合中高强度运动

2. 那么为什么在阳气收敛的时候，进行大重量训练，效果还好?
   * 首先运动表现更好了，做的质量、数量更多，对肌肉刺激更大，恢复过后自然增肌效果更好
   * 并且虽然阳气收敛，但不代表运动表现会变差
   * 甚至可以猜测，白天收回来的阳气，聚集在一起比较浓，反而促进身体内部运转
   * 而且阳气也会直接进入到肌肉里面，补充buff(肌肉消耗气血，阳气推动身体运作、气血流通和合成)

3. 并且因人而异
   * 生物钟整体后延，结果理想睡觉时刻，身体还挺活跃，阳气还没有收敛
   * 年轻人、阳气足的人比较耐造

4. 总的来说，晚上阳气收敛，但是增肌效果还好，可能因为**个人体质、内敛的阳气给身体/肌肉增加buff**

5. 疑点
   * 晚上锻炼未必消耗比较多的阳气??
   * 阳气收敛，但程度不一样，收敛10%、80%也是收敛
   * **我的已知信息并不够、考虑也不到位，推理很可能有漏洞**


## (三)4.25.周六
### 1、对饭后洗澡的探究
1. 干饭，血液集中在胃部

2. 洗澡(温热水澡)加速血液在身体里面流通

3. 于是通常建议饭后不慌洗澡，因为消化系统的血液供给变少

4. 然而根据经验，饭后不消化、有点胀(包括过了几个小时还是比较胀、甚至有点想吐)，马上去洗澡反而更舒服

5. 于是在想，饭后确实血液集中到胃部，但会不会来了太多血液，加上吸收物质比较多，造成血液黏稠、血管堵塞

6. 反正就是不流通，而此时洗澡刚好促进血液流通，把各种物质排走，多的血液也流走，让胃部血液比较平衡，就比较舒服

7. 个人的话通常是下午锻炼完 → 干饭 → 洗澡 → 舒服，不过身体接触热水前，先用热水在肚子上抹几圈，类似游泳之前先让肚子适应水温

8. 总的来说，饭后应该也是可以马上洗澡的，不过因人而异，保险起见还是散会儿步再来


### 2、给人写提示词
为了让AI干活的效果更好，我们会写出高质量的提示词(甚至再让AI自己优化一下)喂给AI，于是AI可以更清楚任务的背景、目的、示例/达成效果、约束等等

那么可以给人写提示词，让人遵守约束、定位，让人去完成目标要求吗?

我觉得理论上是可以的(毕竟都可以角色扮演)，而且人的潜力还是有的，大部分要求都可以做到，除了部分情况会偏移提示词约束，按照自己的想法、感觉去做，就类似AI有自己的幻觉、并不会完全按照提示词进行

不过最难的在于人自己的动机，必须有足够的动机才可以让人长期按照提示词进行(不过可能也比AI更持久了，逮着AI同1个对话框连续对话几天、不开新对话，我觉得AI应该会炸)

然后还要看这个人的执行力、自觉程度、服从性等等，以及多次训练……

不过应该是可以给人写提示词的，真就跟AI差不多的效果我想的话(可能这就是人机🤣)


### 3、对食堂并发问题的探究
1. 已知食堂常见布局: 
   * 1组区域 = M个窗口 + N个刷卡机 + X个叔叔阿姨
   * X可能比较少 = 1, 2...

2. 规则: 
   * 忽略扫码支付，只考虑刷饭卡
   * 在刷卡机那里排队
   * 叔叔阿姨优先给近的学生 || 呼叫他们的学生打菜

3. 进程空等待问题:
   * 学生A进入某刷卡机队列
   * 然而叔叔阿姨都在另外几个刷卡机a, b，正在被占用
   * a, b的队列持续增长，且有人直接呼叫，持续调用叔叔阿姨，赶不过来(并且可能也没注意到A)
   * 于是学生A虽然比其他学生早到，但并不能早刷卡
   * (这是我...)

4. 解决方法
   * 首先是增加叔叔阿姨的数量，系统的处理器数量足够多，可以用火力压制一切 == 食堂人员有限
   * 然后是提高叔叔阿姨的打菜速度，处理器效率高就可以一对多 == 打菜快了会撒，而且高峰期不是1个员工打菜快就可以解决的
   * 学生的话，就需要提前观察叔叔阿姨的位置，去近的队列，并且尽量喊一喊，优先解决自己 == 虽然可能不能让叔叔阿姨均匀解决每个刷卡机排队的人

5. 继续探究
   * 打菜的叔叔阿姨虽然人数安排有限，但是理论上应该可以自由移动
   * 于是从复用的角度看，应该移动到调用量大的地方，加快拥挤队列疏通，调用量小的地方完全可以处理，这样可以拉低总体的耗时
   * 如果硬要说叔叔阿姨固定在原地，不能长距离移动帮助处理其他窗口
   * 那么可以挤出几个人，组成类似线程池的单位，哪里需要发哪里

6. 然而食堂终究还是要面对超高并发
   * 我们可以看到食堂已经有的策略是**分流**
   * 足够多的食堂、开2楼，足够多的摊点、窗口，不同的需求就可以筛出不同的队列
   * 然而人数实在是太多，队列依然很长
   * 但也可以发现部分区域还是比较少人
   * 于是可不可以考虑混合区域?不单独区分素菜区、荤菜区(小荤/大荤)、套餐区，直接混合各种价位的菜，各个区域功能一样，于是自然把队列再次均摊到各区域
   * 这样大家要打到各种菜也方便，不需要打素菜来这边、打荤菜去那边
   * 缺点是非常耦合，模块不清晰，可能会管理不方便????(我感觉都那样)
   * 但不管这个，还是会有长队列，除了**分流、增加处理器、处理器加速**，还有没有其他办法??
   * 处理器的主要作用是帮助学生进程拿取菜品资源，而耗时也在这个拿取过程
   * 于是我们可不可以“去除”处理器这个中间过程，直接让学生自行访问资源??类似自助餐??
   * 只需要设置入口、出口，在出口结账即可
   * 所以**长时间等待的原因很可能是进程访问资源的中间过程复杂/冗余**
   * 之后的业务问题就不管了~~~

7. 此外，还有资源访问问题
   * 2个刷卡机排队的同学a,b同时调用叔叔阿姨c,d，并且都指定了同一种菜
   * 此时手快的c会抢先访问这个菜，d则等待
   * 然而这个菜被c打完了，于是d需要反馈给b、等待b的新请求
   * (又是我...)
